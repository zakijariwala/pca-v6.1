### B09-D002 | pillars: cost

A) Partition the table by `event_date`.
B) Cluster on a column no query filters on.
C) Add more slots.

### B09-D003 | pillars: cost, performance
Scenario: A table is partitioned by date. Many queries also filter on `customer_id`. What else helps those queries?
A) Partition by `customer_id` as well.
B) Cluster the table on `customer_id`.
C) Create a view.
D) Add an index as in a relational database.
<details><summary>Answer</summary>
B. Why: clustering sorts storage blocks by up to four columns so filters skip blocks.
A fails: the table is already partitioned by date; clustering is the tool for extra filter columns.
C fails: a view doesn't change scanning.
D fails: the lesson's tools for this are partitioning and clustering, not relational-style indexes.
Verified: 2026-09-24
</details>
