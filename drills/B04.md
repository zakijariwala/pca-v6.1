# B04 drills

### B04-D001 | pillars: reliability, performance
Scenario: A game server uses UDP and must see each player's source IP. Which load balancer family fits?
A) Global external Application Load Balancer.
B) External proxy Network Load Balancer.
C) Passthrough Network Load Balancer.
D) Internal Application Load Balancer.
<details><summary>Answer</summary>
C. Why: passthrough keeps client source IPs and supports UDP.
A fails: HTTP(S) only, and a proxy.
B fails: a proxy terminates connections, so backends don't see the client IP in the packet.
D fails: internal and HTTP(S).
Verified: 2026-09-24
</details>

### B04-D004 | pillars: performance
Scenario: A company needs 5 Gbps to Google Cloud. It has no presence in a Google colocation facility. Which option fits?
A) Dedicated Interconnect.
B) VPC Network Peering.
C) Cloud CDN.
D) Partner Interconnect through a service provider.
<details><summary>Answer</summary>
D. Why: a provider supplies the connection when you can't reach a colocation facility; attachments go up to 50 Gbps.
A fails: needs your router in a colocation facility.
B fails: connects VPC networks.
C fails: caching, not connectivity.

### B04-D008 | pillars: security
Scenario: A SaaS provider must serve 200 customer VPCs, some with overlapping IP ranges. Each customer should reach only the service. What fits?
A) Private Service Connect: customers create endpoints to the provider's service attachment.
B) VPC Network Peering with each customer.
C) Shared VPC across customers.
D) Public load balancer with IP allowlists.
<details><summary>Answer</summary>
A. Why: PSC exposes one service through an internal IP in each consumer VPC; overlapping ranges don't matter.
B fails: overlapping ranges can't peer, and peering exposes whole networks.
C fails: across companies and organizations, not the model.
D fails: public path.
Verified: 2026-09-24
</details>

### B04-D009 | pillars: performance, security
Scenario: A team enables Cloud CDN with `FORCE_CACHE_ALL` on an API that returns per-user account data. What's the risk?
A) No risk; CDN respects user sessions.
B) Higher latency.
C) Responses marked private can be cached and served to other users.
D) Cloud CDN refuses to start.
<details><summary>Answer</summary>
C. Why: `FORCE_CACHE_ALL` caches successful responses and ignores private and no-store directives.
A fails: this mode ignores those directives.
B fails: caching lowers latency; the problem is data exposure.
D fails: it runs.
Verified: 2026-09-24
</details>
