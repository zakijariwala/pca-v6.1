### B05-D001 | pillars: cost, performance
Scenario: An in-memory analytics database needs a high memory-to-vCPU ratio. Which machine family fits?
A) Compute-optimized.
B) Memory-optimized.
C) Storage-optimized.
D) Accelerator-optimized.
<details><summary>Answer</summary>
B. Why: memory-optimized machines offer the most memory per core.
A fails: high performance per core, not memory.
C fails: built for storage density.
D fails: for GPU workloads.

</details>

### B05-D003 | pillars: reliability
Scenario: A stateless web tier must survive the loss of a zone and replace failed VMs on its own. What fits?
A) A zonal MIG with autohealing.
B) Three standalone VMs in one zone.
C) A regional MIG with an application health check for autohealing.
D) One large VM.
<details><summary>Answer</summary>
C. Why: a regional MIG spreads VMs across zones; autohealing recreates failed ones.
A fails: one zone.
B fails: one zone, no repair.
D fails: single point of failure.
Verified: 2026-09-24
</details>

### B05-D007 | pillars: reliability
Scenario: A team needs a daily backup of a VM disk that it can restore in another region. What should it use?
A) Instant snapshots.
B) Standard snapshots on a snapshot schedule.
C) Local SSD.
D) A second disk in the same zone.
<details><summary>Answer</summary>
B. Why: standard snapshots are geo-redundant global resources; schedules take them daily.
A fails: stored in the disk's own zone or region, and schedules can't create them.
C fails: ephemeral.
D fails: same failure domain.
Verified: 2026-09-24
</details>

### B05-D008 | pillars: reliability
Scenario: A MIG keeps recreating VMs during boot, then they turn out healthy. The app takes 3 minutes to start. What should you set?
A) A shorter health check interval.
B) A bigger machine type.
C) An autohealing initial delay longer than 3 minutes.
D) Turn off the health check.
<details><summary>Answer</summary>
C. Why: during the initial delay the MIG ignores failed checks, so booting VMs aren't recreated.
A fails: fails them faster.
B fails: may shorten boot a little, but doesn't fix the policy.
D fails: loses repair.
Verified: 2026-09-24
</details>

### B05-D009 | pillars: security

B) A shared SSH key for the team.
C) Password logins on each VM.
D) OS Login, with access granted through IAM.
<details><summary>Answer</summary>
D. Why: OS Login checks IAM, so removing the role or group membership ends access everywhere.
A fails: keys must be found and removed by hand.
B fails: everyone must rotate.
C fails: per-VM changes.

</details>

### B05-D010 | pillars: operational-excellence
Scenario: A legacy app can't be modified, needs a specific OS version, and runs as a long-lived stateful process. Where should it run?
A) Cloud Run.
B) Compute Engine.
C) Cloud Run functions.
D) App Engine standard.
<details><summary>Answer</summary>
B. Why: VMs give OS control for apps that can't be containerized or changed.
A fails: needs a container that fits Cloud Run's model.
C fails: event-driven code, not a long-lived process.
D fails: needs app changes and isn't recommended for new deployments.
Verified: 2026-09-24
</details>
