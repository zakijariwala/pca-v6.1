### B21-D001 | pillars: security, reliability
Scenario: A payments API on Cloud Run reads a Cloud SQL database on a private IP. Security wants no service account keys, and the database must survive a zone failure. Which design meets both?
A) Cloud SQL HA with a public IP; the app uses a key file to authenticate.
B) Cloud SQL HA with private IP only; Cloud Run with its own service account and Direct VPC egress.
C) Single-zone Cloud SQL with daily backups; Direct VPC egress.
D) Firestore; a key file in Secret Manager.
<details><summary>Answer</summary>
B. Why: HA covers the zone; a dedicated service account avoids keys; Direct VPC egress reaches the private IP.
A fails: public exposure and a key file.
C fails: a zone failure takes the database down.
D fails: changes the data model and still uses a key.
Verified: 2026-09-24
</details>

### B21-D002 | pillars: cost, reliability
Scenario: A media company stores master files read less than once a year and must keep them unchanged for 7 years, even from admins. Which combination fits?
A) Archive class with a retention policy locked by Bucket Lock.
B) Standard class with object versioning.
C) Nearline class with soft delete at 90 days.
D) Local SSD snapshots.
<details><summary>Answer</summary>
A. Why: Archive fits data read less than once a year; a locked retention policy can't be reduced or removed.
B fails: a pricier class, and versions can be deleted.
C fails: soft delete covers at most 90 days.
D fails: Local SSD is ephemeral and snapshots aren't a records store.
Verified: 2026-09-24
</details>

### B21-D003 | pillars: operational-excellence, security
Scenario: A GitHub pipeline must run `terraform plan` against production and post the result, with no keys and read-only access. What's the setup?
A) A service account key with Owner, stored in GitHub.
B) A developer's personal credentials.
C) Workload Identity Federation to impersonate a read-only plan service account with access to the state bucket.
D) Cloud Source Repositories with a trigger.
<details><summary>Answer</summary>
C. Why: keyless federation plus a least-privilege service account for plans.
A fails: a key, and far too much access.
B fails: ties CI to a person.
D fails: closed to new customers, and doesn't solve authentication.
Verified: 2026-09-24
</details>

### B21-D004 | pillars: reliability, operational-excellence
Scenario: A team's SLO burn-rate alert fires during a canary rollout on Cloud Deploy. What's the right response?
A) Promote the release to 100% to spread the load.
B) Silence the alert until the rollout finishes.
C) Add replicas to the canary.
D) Roll back the canary, then investigate before promoting again.
<details><summary>Answer</summary>
D. Why: the canary exists to catch this; rollback limits impact.
A fails: spreads the failure to everyone.
B fails: hides the signal the canary exists to produce.
C fails: more capacity doesn't fix a bad release.
Verified: 2026-09-24
</details>

### B21-D005 | pillars: security
Scenario: A healthcare analytics project must stop stolen credentials from copying data out, and analysts must never see patient names. Which pair of controls?
A) CMEK and Cloud Armor.
B) VPC Service Controls around the project, and Sensitive Data Protection to de-identify names.
C) IAP and Cloud CDN.
D) A budget alert and labels.
<details><summary>Answer</summary>
B. Why: the perimeter blocks exfiltration; de-identification removes names from what analysts see.
A fails: keys and edge protection don't stop copying or hide fields.
C fails: access to apps and caching.
D fails: cost controls.
Verified: 2026-09-24
</details>
