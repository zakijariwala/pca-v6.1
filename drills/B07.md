# B07 drills

### B07-D001 | pillars: cost
Scenario: Backups are written daily and restored about once a month for tests. They're kept for 60 days. Which storage class fits best?
A) Standard.
B) Nearline.
C) Archive.
D) Local SSD.
<details><summary>Answer</summary>
B. Why: Nearline fits data read about once a month; its 30-day minimum is under the 60-day retention.
A fails: pays for frequent access that doesn't happen.
C fails: the 365-day minimum exceeds the 60-day retention, and reads cost more.
D fails: ephemeral block storage.
Verified: 2026-09-24
</details>

### B07-D002 | pillars: cost, performance
Scenario: A team believes Archive storage is slow to read, like tape. What's true?
A) Archive takes hours to restore.
B) Archive needs a restore request first.
C) All Cloud Storage classes give millisecond access; Archive costs more to read and has a 365-day minimum.
D) Archive is only reachable from one region.
<details><summary>Answer</summary>
C. Why: the classes differ in price and minimums, not access latency.
A fails: no multi-hour restore.
B fails: no separate restore step.
D fails: location depends on the bucket, not the class.
Verified: 2026-09-24
</details>

### B07-D003 | pillars: reliability
Scenario: Object data must survive a region outage with a recovery point objective of 15 minutes. Which bucket setup?
A) A regional bucket.
B) A multi-region bucket with lifecycle rules.
C) Two regional buckets synced weekly.
D) A dual-region bucket with turbo replication.
<details><summary>Answer</summary>
D. Why: turbo replication replicates new objects within 15 minutes across the region pair.
A fails: one region.
B fails: lifecycle rules don't set replication speed.
C fails: weekly is far past 15 minutes.
Verified: 2026-09-24
</details>

### B07-D004 | pillars: cost
Scenario: A bucket's access pattern is unknown and varies by object. The team wants classes chosen per object without writing rules. What should it enable?
A) Autoclass.
B) Object versioning.
C) Bucket Lock.
D) Soft delete.
<details><summary>Answer</summary>
A. Why: Autoclass moves each object to colder classes when unread and back to Standard when read.
B fails: keeps old versions; no class changes.
C fails: retention enforcement.
D fails: recovery of deleted objects.

</details>

### B07-D006 | pillars: security, reliability
Scenario: A regulator requires records that no one, admins included, can delete or shorten retention on for 7 years. What should you use?
A) Object versioning.
B) A retention policy on the bucket, locked with Bucket Lock.
C) Soft delete set to 90 days.
D) IAM with no delete role granted.
<details><summary>Answer</summary>
B. Why: once locked, the retention policy can't be reduced or removed.
A fails: someone with the right role can still delete versions.
C fails: covers at most 90 days of recovery.
D fails: an admin can grant the role later.
Verified: 2026-09-24
</details>

### B07-D007 | pillars: security
Scenario: A customer without a Google account must download one private invoice PDF, valid for a few hours. What fits?
A) Make the bucket public.
B) Grant the customer's email Storage Admin.
C) Email the file as an attachment from a VM.
D) A V4 signed URL with a short expiry.
<details><summary>Answer</summary>
D. Why: a signed URL grants time-limited access to one object; V4 URLs last at most 7 days.
A fails: exposes every object.
B fails: needs a Google identity and grants far too much.
C fails: builds a workaround for a built-in feature.
Verified: 2026-09-24
</details>

### B07-D008 | pillars: performance, reliability
Scenario: A batch job needs very fast scratch space for temporary files it can regenerate. Which disk type fits?
A) Local SSD.
B) Hyperdisk Balanced High Availability.
C) A Cloud Storage bucket.
D) Filestore Regional.
<details><summary>Answer</summary>
A. Why: host-attached, fastest; data loss on stop is acceptable for regenerable scratch data.
B fails: durable and replicated, which the job doesn't need.
C fails: object storage, not a local disk.
D fails: network file storage, slower than local disk.
Verified: 2026-09-24
</details>
