### B11-D001 | pillars: security
Scenario: A company must control its own encryption keys for data at rest: set rotation, disable a key, and audit key use. Keys may live in Google Cloud. Which option fits?
A) Google default encryption.
B) Customer-managed encryption keys (CMEK) in Cloud KMS.
C) Customer-supplied encryption keys (CSEK).
D) No encryption.
<details><summary>Answer</summary>
B. Why: CMEK gives the customer control over key lifecycle and use, with keys in Cloud KMS.
A fails: Google controls the keys.
C fails: supported by few services, and losing the key loses the data.
D fails: data at rest is always encrypted; the question is key control.
Verified: 2026-09-24
</details>

### B11-D003 | pillars: security

A) Cloud HSM.

### B11-D004 | pillars: security
Scenario: A team scheduled a Cloud KMS key version for destruction by mistake this morning. What can it do?
A) Nothing; destruction is immediate.
B) Open a support case after 30 days.
C) Create a new key with the same name.
D) Restore the key version during the scheduled-for-destruction period, 30 days by default.
<details><summary>Answer</summary>
D. Why: key versions wait in a scheduled state before destruction and can be restored in that window.
A fails: destruction isn't immediate.
B fails: after the period the version is gone.
C fails: a new key can't decrypt data encrypted with the old one.
Verified: 2026-09-24
</details>

### B11-D005 | pillars: security
Scenario: An app's database password sits in an environment variable baked into its container image. What's the better design?
A) Store it in a Cloud Storage object.
B) Store it in Secret Manager; the app reads it at runtime with its service account, and access is audited.
C) Put it in the Git repository, encrypted with a shared password.
D) Hard-code it in the source.
<details><summary>Answer</summary>
B. Why: versioned secrets, IAM-controlled access, and audit logs.
A fails: not built for secrets, and easy to expose.
C fails: shared passwords and secrets in Git.
D fails: exposed to anyone with the code.
Verified: 2026-09-24
</details>
