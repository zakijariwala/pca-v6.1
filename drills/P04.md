### P04-D001 | pillars: reliability
Scenario: A VPC-native GKE cluster can't add nodes, with an `IP_SPACE_EXHAUSTED` error, yet the primary subnet has free addresses. What's the cause?
A) The primary subnet is too small.
B) The Pod secondary range has run out of per-node blocks.
C) The cluster hit a CPU quota.
D) A firewall rule blocks new nodes.
<details><summary>Answer</summary>
B. Why: each node reserves a block from the Pod range; when blocks run out, nodes can't be added.
A fails: Pods don't use the primary range.
C fails: a quota error names the quota, not IP space.
D fails: firewalls don't allocate IPs.
Verified: 2026-09-24
</details>

### P04-D002 | pillars: reliability
Scenario: With max Pods per node at 110 and a /21 Pod range, how many nodes can the cluster hold?
A) 8.
B) 16.
C) 110.
D) 2,048.
<details><summary>Answer</summary>
A. Why: at 110 Pods per node each node takes a /24; a /21 holds 2^(24-21) = 8.
B fails: would need a /20.
C fails: that's Pods per node.
D fails: that's addresses in a /21, not nodes.
Verified: 2026-09-24
</details>

### P04-D007 | pillars: reliability

A) Remove the PDB.

### P04-D009 | pillars: operational-excellence
Scenario: A container exits with code 137, and `Last State` shows `OOMKilled`. What happened?
A) The container went over its memory limit and the kernel OOM killer ended it.
B) The image couldn't be pulled.
C) The node ran out of disk.
D) The liveness probe URL was wrong.
<details><summary>Answer</summary>
A. Why: exit code 137 with OOMKilled means an out-of-memory kill.
B fails: shows as ImagePullBackOff.
C fails: a different eviction reason.
D fails: probe failures show as restarts with probe messages, not OOMKilled.
